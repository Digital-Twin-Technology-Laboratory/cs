# 本科教学大纲检查系统

教师注册账号并上传教学大纲，系统按管理员维护的《本科教学大纲通用检查清单》调用 AI 逐项检查，生成规范的修改清单，教师可下载（Word）或复制。每次上传独立检查，所有上传文件和检查结果都会保存。

初始检查清单取自《教学大纲检查网站 新会话交接说明》第4节（2026年11月3日版，已合并5处修改）。本轮统一以 2025 级相应专业人才培养方案为对照起点。

## 运行环境

- Node.js 22.13 及以上（使用 Node 内置的 SQLite，无需安装数据库）
- Windows / macOS / Linux 均可

## 启动

首次使用先安装依赖：

```bash
npm install
```

正式使用（构建后单端口运行，默认端口 3000）：

```bash
npm run build
```

```bash
npm start
```

启动后浏览器打开 `http://localhost:3000`。同一局域网内的其他电脑使用控制台打印的 `http://本机IP:3000` 访问（需允许 Windows 防火墙放行该端口）。

开发调试（前端 5173 热更新，后端 3000）：

```bash
npm run dev
```

可用环境变量：`PORT`（端口，默认 3000）、`HOST`（监听地址，默认 0.0.0.0）、`DATA_DIR`（数据目录，默认项目下 `data/`）。

## 首次使用

1. **第一个注册的账号自动成为管理员**（不受注册开关限制）。注册后会自动进入“AI 配置”。
2. 在“AI 配置”中填写接口并点“测试连接”：
   - OpenAI 兼容接口：DeepSeek、通义千问、Kimi、智谱等国内模型，填写 Base URL、API Key、模型名称；
   - Anthropic Claude：填写 API Key 和模型名称（默认 `claude-opus-5-5`）。
3. 在“培养方案管理”中按 专业 + 培养类型 + 年级 上传 2025 级人才培养方案（docx/pdf）。可在线修订提取的文本，保留毕业要求指标全文、课程设置表和课程支撑矩阵。
4. 在“系统设置”中选择注册方式：开放注册 / 注册需审核 / 关闭注册。

## 功能

**教师（普通用户）**

- 上传检查：填写课程名称、专业、培养类型、学生年级、对照方案年级（默认 2025，调整须说明），上传 .docx 或 .pdf 大纲；
- 查看结果：结论（无明确问题和重大问题即通过）、修改清单（明确问题及重大问题 / 建议修改 / 需核实事项，每条列所在位置、当前问题、整改意见）、逐项检查结果及原文依据；
- 下载修改清单 Word、复制文本、打印、下载原文件；
- 我的课程：每门课程的历次检查记录；
- 检查清单：浏览当前清单，支持关键词搜索和按部分筛选。

**管理员**

- 概览、用户管理（审核注册、新建、停用/启用、设为管理员、重置密码、删除账号及其文件）；
- 文件与检查记录：全站课程与每次上传的文件、修改清单，可筛选、下载、删除，对失败记录重新检查；
- 检查清单管理：在线编辑、上传 docx/txt/md 导入（预览确认后保存）、版本管理与设为生效；已被使用的版本修改时自动另存为新版本；
- 培养方案管理、AI 配置（含检查提示词）、系统设置、操作日志。

## 检查规则要点

- 每次检查只使用本次上传的大纲、当前生效清单和对应培养方案，不参考以往记录；
- “需核实”事项（签字、纸质归档、实验记录、成绩单等仅凭大纲无法确认的内容）单列，不计入问题、不影响通过；
- 修改清单不出现 C01/M03 等内部编号、原文摘录和处理先后顺序；问题编号只用于识别和引用；
- 未预置对应培养方案时仍可检查，需要比对方案的内容列为需核实；
- AI 结果只读；检查失败（接口错误等）可重新检查，已完成的结果不覆盖。

## 数据与备份

所有数据在 `data/` 目录：`app.db`（数据库）、`uploads/`（教师上传的大纲）、`plans/`（培养方案原文件）、`secret.key`（API Key 加密密钥）。备份时停止服务后复制整个 `data/` 目录即可；`secret.key` 丢失后需重新填写 API Key。

## 开发测试工具

- `node scripts/mock-ai.mjs 3999`：本地模拟的 OpenAI 兼容接口（Base URL 填 `http://localhost:3999/v1`），不调用真实模型，用于测试流程；
- `node scripts/make-sample-syllabus.mjs 输出.docx`：生成一份考核表合计故意写错的测试大纲。
