# 教学材料检查系统

统一使用工号或姓名加密码登录。管理员导入的教师使用初始密码 `12345678`，登录后可直接使用系统，不强制修改密码；管理员新建账号和重置密码后也可直接使用。用户可在个人设置中自行修改密码。上传教学大纲后，系统按管理员维护的检查清单调用 AI 检查，生成可下载的 Word 结果，保留上传与检查历史。

初始检查清单基于《教学大纲检查网站 新会话交接说明》第4节（2026年11月3日版，已合并5处修改），现限定为只检查教学大纲，并以 2025 级相应专业人才培养方案为对照起点。旧默认清单在升级时自动另存为新版本，历史清单与检查结果保留；自定义清单原文不变，新检查统一受大纲检查范围约束。

## 运行环境

- Node.js 22.13 及以上（使用 Node 内置的 SQLite，无需安装数据库）
- Windows / macOS / Linux 均可

## 启动

首次使用先安装依赖：

```bash
npm install
```

正式使用（构建后单端口运行，默认端口 3000）：

```bash
npm run build
```

```bash
npm start
```

启动后浏览器打开 `http://localhost:3000`。同一局域网内的其他电脑使用控制台打印的 `http://本机IP:3000` 访问（需允许 Windows 防火墙放行该端口）。

开发调试（前端 5173 热更新，后端 3000）：

```bash
npm run dev
```

可用环境变量：`PORT`（端口，默认 3000）、`HOST`（监听地址，默认 0.0.0.0）、`DATA_DIR`（数据目录，默认项目下 `data/`）。

## 首次使用

1. **第一个注册的账号自动成为管理员**（不受注册开关限制）。注册后会自动进入“AI 配置”。
2. 在“AI 配置”中填写配置名称、接口地址和 API Key，点击“获取模型”，搜索并选择模型，再“测试连接”和“保存配置”（获取、测试均无需先保存）。可新增多套独立配置，每套分别保存接口、密钥、模型、参数和提示词；选择配置后点击“使用此配置”切换。第一套自动启用，旧版配置自动保留为“默认配置”。正在进行的检查保留启动时的配置，后续任务使用当前启用的配置：
   - OpenAI 兼容接口：DeepSeek、通义千问、Kimi、智谱等国内模型，填写服务商提供的 Base URL；
   - Anthropic Claude：使用官方接口时地址留空；使用代理或企业网关时填写其地址；
   - 编辑已有配置时，API Key 留空表示保留该配置的 Key；新增配置必须填写独立 Key，不会借用其他配置的密钥。服务商不支持模型列表时，可手动填写模型名称。
3. 在“培养方案管理”中上传人才培养方案（docx/pdf/txt/md），系统根据文件名或正文标题自动识别专业及培养类型，识别不明确时手动选择，也可修正识别结果。确认专业、培养类型及年级后保存；可在线修订提取的文本，保留毕业要求指标全文、课程设置表和课程支撑矩阵。
4. 在“系统设置”中选择注册方式：开放注册 / 注册需审核 / 关闭注册。
5. 在“用户管理 → 导入教工名单”上传 Excel（.xlsx，第一个工作表）或 UTF-8 CSV，第一行含“姓名”和“工号”，工号用文本保留前导零。新账号使用工号或姓名和初始密码 `12345678` 登录，无需修改密码即可使用系统。已有工号跳过，不覆盖账号；旧账号的强制改密标记不再限制使用，登录后自动清除。
6. 在“视图与执笔人配置”同步腾讯云文档，或导入云表导出的 Excel / CSV。清单须含“课程名称、课程组、审核专业、大纲执笔人”，不再使用整周课表或磨课表。云表更新后须主动重新同步；同步保留同一课程的手工执笔人配置，不修改账号、密码或检查记录。

## 功能

**教师（普通用户）**

- 批量上传检查：先选择人才培养方案年级（2023、2024、2025、2026，默认 2025），不再单独选择培养类型；一次选择多个 .docx 或 .pdf 大纲，每个文件一行，课程名称默认取文件名（可修改），也可从云清单的去重课程名称中选择，不按审核专业过滤、不带专业和执笔人信息、不自动回填专业。逐行手动选择学生年级（23、24、25、26）和专业（计算机科学与技术、计算机科学与技术（专转本）、物联网工程、人工智能）。专转本自动匹配对应培养方案，调整方案年级无需填写说明；
- 每日限额：每个账号每天基础额度为 5 次，管理员可为指定用户追加当天次数，次日按服务器本地时间零点恢复基础 5 次。生成结果即计次（无论大纲是否通过）；接口或解析失败不计次。排队和检查中的任务暂占名额，失败后释放，批量上传及重新检查均受限制。右上角显示剩余次数，次数用完提示联系管理员；
- 查看结果：结论（无明确问题和重大问题即通过）、检查结果（明确问题及重大问题 / 建议完善 / 需核实事项）、逐项检查结果及原文依据；上传记录与结果开头提示 AI 结果可能存在遗漏或误判，由教师结合实际自主采纳、修改并确认提交。网页、Word 和复制文本均包含使用提示及相关材料一致性提醒；每条意见按 A01 / B01 编号列出位置、问题、整改意见；
- 在结果页醒目的“下载检查结果（Word）”入口下载，也可在上传记录、课程记录中直接下载；支持复制文本、打印、下载原文件；
- 确认提交与撤回上传：检查完成后由上传者点击“确认提交”，无论检查是否通过均可提交。原上传者可撤回已确认的结果（包括组长代确认的结果），提交状态变为“未上传”，清除确认人及时间；若撤回的是课程最新结果，个人、全院、专业、课程组进度同步恢复未上传，不退回采用旧版结果。原文件、检查结果及历史记录保留，不返还已使用的检查次数；可直接再次确认提交，无需重新检查。撤回历史版本不影响最新版本的进度；
- 上传记录：查看自己的全部上传历史，按关键词、检查状态、提交状态（含已撤回）筛选；已确认项可直接撤回上传。批量上传中失败的文件可单独重试，成功记录不重复上传；
- 我的课程：每门课程的历次检查记录；
- 个人总览：仅统计云清单中绑定本人为执笔人的任务，显示已上传、通过、确认的分子 / 应交分母。按课程名称（忽略大小写）＋审核专业＋课程组＋执笔人去重平行班，不同执笔人分别计应交任务；每项任务取最新上传的结果，不限实际上传人。所有应交项通过才算个人全部通过。云清单仅用于总览展示和进度统计，不作为上传门槛；账号或执笔人不同、课程或专业不匹配、同名任务不唯一、所选任务已失效均不阻止上传。匹配明确时自动关联，也可从“课程名称”下拉列表辅助选择；无法明确关联的上传保留检查记录，不误计入其他任务的进度。文件格式、大小、必填课程信息及检查次数等正常校验不变；
- 上传前自查：上传页顶部可下载教学大纲模板原文件（包含理论课、课程设计、实习实训及毕业论文等格式），同时展示检查清单要点，可下载当前生效清单的完整 Word 文件（含各部分说明和判定规则）；每行选择专业后显示对应方案及下载入口，随所选方案年级自动更新。方案年级右侧也可下载该年级各专业已启用的方案原文件。未匹配方案时明确提示，仍可检查，方案比对项列为需核实。

**管理员**

- 概览、用户管理（导入教工名单、审核注册、新建、停用/启用、设为管理员、重置密码、删除账号及其文件、增加今日检查次数）；用户姓名和工号集中展示，窄屏表格改为纵向记录；
- 大纲进度全览：与云清单同一份数据，每 10 秒刷新，默认逐门课程显示上传 / 应交、通过 / 应交、确认 / 应交；人员进度为辅助视图。执笔人待定仍计入课程总数，可以上传、查看、由组长最终确认，实际上传人单独记录，暂不计入个人应交。未匹配或同名账号保留任务，可手动绑定；调整执笔人只改变个人责任归属，不清空课程已有上传与确认；
- 文件与检查记录：全站课程与每次上传的文件、检查结果、提交状态及时间，可按用户、专业、学生年级、课程组、检查状态、结论、提交状态（含已撤回）和上传日期筛选。跨页勾选后可批量查看原文与结果、打包下载原文件或已完成的 Word 检查结果，每次最多100条，同名文件按记录编号区分；也可删除、重新检查失败记录。用户管理中的检查次数可进入该用户的上传历史，管理员不能代其他用户确认或撤回结果；
- 检查清单管理：在线编辑、上传 docx/txt/md 导入（预览确认后保存）、版本管理与设为生效；已被使用的版本修改时自动另存为新版本；
- 培养方案管理、AI 配置（含检查提示词）、系统设置、操作日志。

**监督身份（独立于管理员，可兼任）**

- root 等系统管理员和获授权的汤家华可进入“视图与执笔人配置”，逐账号配置身份、课程组及审核专业。升级时仅将已有唯一匹配的汤家华账号绑定为配置人员；未匹配时由管理员手工授予。权限绑定账号 ID，之后改名不会授予权限；仅系统管理员能转授配置权，配置人员不因此获得账号管理或 AI 配置权；
- 教学条线查看全院，可从“全院总览 → 全院检查记录”或“上传记录”的范围下拉查看、下载所有上传结果，包括未关联云清单的记录；应交课程进度仍按云清单统计。专业负责人仅查看所配置的审核专业；课程组长仅查看负责课程组。可兼任并切换已授权视图，专业身份尚未指定专业时显示配置提示，不开放其他专业。可以保留预设人员匹配入口，但实际专业范围由管理员手工配置；
- 教学条线的全院检查记录支持专业、学生年级、课程组、检查状态、结论、确认状态、日期及关键词筛选与批量查看、ZIP 下载。全院、专业、课程组总览可按授权课程组、专业、课程状态或关键词筛选，在“逐门课程”跨页勾选，批量查看、下载课程的最新附件；服务端逐条校验权限，不能通过批量入口访问其他范围的记录。
- 刘正涛、龚兰兰、薛亮的唯一姓名匹配账号在升级时一次性补齐专业负责人身份，管理员新建、导入这些账号或按预设授权时也会补齐。负责专业仍由 root 或汤家华手动分配，不根据姓名猜测；未配置前可见专业总览入口及配置提示，不显示其他专业数据。保留已手动配置的专业及后续撤销；同名账号须手动绑定，注册或自行改名不会实时获得授权；
- 八个正式课程组取自大纲云清单，不按磨课时间筛选。未分组任务仍计入全院，未配置审核专业的任务暂不归入专业视图；
- 升级时按八组预设，为唯一姓名匹配的组长账号一次性补齐对应课程组视图，管理员新建或导入这些账号时也会补齐；已有手动组长配置优先，不覆盖已占用的课程组，后续撤销不会因重启恢复。同名或未建账号由 root 或汤家华手工绑定；
- 组长在“课程组总览”或结果页查看大纲提取原文、下载原文件并最终确认已完成的最新检查。组长确认直接写入最终确认状态，记录确认人、工号和时间，同步个人总览和管理员，无需教师再次确认。确认不改变 AI 通过结论；重新上传需确认新结果。只有全院查看身份而未兼任相应组长的人不能代组长确认。权限撤销即时在服务端生效。

## 检查规则要点

- 每次检查只使用本次上传的大纲、当前生效清单和对应培养方案，不参考以往记录；
- 仅检查大纲本身及其与培养方案的对应关系，不检查教案、教学进度表、实验记录、成绩单、外部评分标准、纸质签字或归档手续，不因未提供这些材料判错或列为需核实；大纲修改后的跨材料一致性仅在“建议完善”中提醒，不影响通过。大纲本身的评分要点、学时、考核比例等要求仍需检查；
- 检查结果不出现 C01/M03 等内部编号、原文摘录和处理先后顺序；A01/B01 等问题编号只用于识别和引用；
- 未预置对应培养方案时仍可检查，需要比对方案的内容列为需核实；
- PDF 课程支撑矩阵按本页表头和单元格坐标补充“指标编号=H/M/L”，避免空白列丢失后错配指标。无法可靠定位的关系保留原文并注明需核实，不按 H/M/L 出现顺序猜测。升级前已保存的方案可由管理员在“培养方案管理”点击“重新提取”，确认覆盖人工修订后直接从服务器原文件更新文本，无需重传；原文件、方案信息及旧检查结果不变。原文件缺失或提取失败时保留现有文本，缺失文件需重新上传；旧检查结果不会自动重算。
- 原 AI 检查明细保留；普通用户只读，管理员或教学条线（全院）可手工调整已完成记录的通过结论，详情和下载报告注明修改人及时间。检查失败（接口错误等）可重新检查，不重新覆盖已完成的 AI 明细。

## 手工修改数字

不显示编辑按钮，仅管理员可双击个人总览、监督总览及人员进度中的数字进入编辑，回车或移开焦点保存，Esc 取消。普通用户仍为只读，服务端也拒绝非管理员写入；旧版示意权限不再生效。

统计数字作为手工修正值保存到数据库，刷新或重启后保留，有相应查看权限的其他账号也能看到；不更改应交课程、上传文件、检查结果或确认状态。清空某个统计数字再保存，可移除该修正值，恢复自动统计。筛选后的数字独立保存；不筛选时，人员进度中的修正值与该教师的个人总览共享。

上传记录的编辑仅开放给管理员或“教学条线（全院）”身份。在“上传记录”中，查看他人记录时将范围切到“全院检查记录”，双击课程、年级、专业、文件名或次数即可修改；已完成记录的检查结果直接显示下拉框，无需双击，可将“未通过”改为“已通过”。文本回车或移开焦点保存，选择项选定即保存，Esc 取消；检查进行中不能修改课程信息或结论。次数须大于零。每次保存真实写入数据库并记录操作日志，刷新后保留，详情和下载报告同步。

改文件名不替换原文件内容；手工修改结论不删除原 AI 问题明细，也不更改结果确认状态，报告会注明修改人及时间。已绑定的应交任务不因改名或改专业而解除绑定。原来的示意按钮和临时假记录不再使用。

真实上传记录的“次数”按上传人、应交课程（名单外按课程名称，忽略大小写）、审核专业、培养类型、学生年级累计；更换文件名或培养方案年级不重置次数。升级会校正相同标识的旧记录序号，不改动原检查结果。课程名称不同且未绑定同一应交课程时，不自动猜测并合并。

## 数据与备份

所有数据在 `data/` 目录（设置 `DATA_DIR` 时以该目录为准）：`app.db`（数据库）、`uploads/`（教师上传的大纲）、`plans/`（培养方案原文件）、`secret.key`（API Key 加密密钥）。

管理员在“系统设置 → 数据备份”点击“下载备份”，即可不停服下载包含上述数据的 ZIP 文件，并记录操作日志。数据库通过 SQLite 快照备份，包含已提交到 WAL 的数据，不直接复制运行中的数据库；临时文件和 WAL/SHM 文件不打包。生成快照和读取附件时会短暂占用服务，建议低峰操作。备份包含账号数据及密钥，请妥善保管并另存到其他设备；本功能不包含定时备份。

恢复时先停止服务，将原数据目录整体移走保留，再将 ZIP 中的 `data/` 目录放到实际数据目录位置（使用 `DATA_DIR` 时恢复到其指定位置），然后启动同版本服务。不要直接合并覆盖运行中的数据或保留旧的 WAL/SHM 文件。也可停服后手工复制整个数据目录备份；`secret.key` 丢失后需重新填写 API Key。

- `node scripts/make-sample-syllabus.mjs 输出.docx`：生成一份考核表合计故意写错的测试大纲。
