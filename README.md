# 教学材料检查系统

管理员导入的教师首次使用工号和姓名激活账号，登录后会告知初始密码 `12345678`，可在“个人设置”中修改；之后使用工号或姓名加密码登录，同名时使用工号。也可注册账号并使用密码登录。上传教学大纲后，系统按管理员维护的《本科教学大纲通用检查清单》调用 AI 逐项检查，生成规范的检查结果，教师可下载（Word）或复制。每次上传独立检查，所有上传文件和检查结果都会保存。

初始检查清单取自《教学大纲检查网站 新会话交接说明》第4节（2026年11月3日版，已合并5处修改）。本轮统一以 2025 级相应专业人才培养方案为对照起点。

## 运行环境

- Node.js 22.13 及以上（使用 Node 内置的 SQLite，无需安装数据库）
- Windows / macOS / Linux 均可

## 启动

首次使用先安装依赖：

```bash
npm install
```

正式使用（构建后单端口运行，默认端口 3000）：

```bash
npm run build
```

```bash
npm start
```

启动后浏览器打开 `http://localhost:3000`。同一局域网内的其他电脑使用控制台打印的 `http://本机IP:3000` 访问（需允许 Windows 防火墙放行该端口）。

开发调试（前端 5173 热更新，后端 3000）：

```bash
npm run dev
```

可用环境变量：`PORT`（端口，默认 3000）、`HOST`（监听地址，默认 0.0.0.0）、`DATA_DIR`（数据目录，默认项目下 `data/`）。

## 首次使用

1. **第一个注册的账号自动成为管理员**（不受注册开关限制）。注册后会自动进入“AI 配置”。
2. 在“AI 配置”中填写配置名称、接口地址和 API Key，点击“获取模型”，搜索并选择模型，再“测试连接”和“保存配置”（获取、测试均无需先保存）。可新增多套独立配置，每套分别保存接口、密钥、模型、参数和提示词；选择配置后点击“使用此配置”切换。第一套自动启用，旧版配置自动保留为“默认配置”。正在进行的检查保留启动时的配置，后续任务使用当前启用的配置：
   - OpenAI 兼容接口：DeepSeek、通义千问、Kimi、智谱等国内模型，填写服务商提供的 Base URL；
   - Anthropic Claude：使用官方接口时地址留空；使用代理或企业网关时填写其地址；
   - 编辑已有配置时，API Key 留空表示保留该配置的 Key；新增配置必须填写独立 Key，不会借用其他配置的密钥。服务商不支持模型列表时，可手动填写模型名称。
3. 在“培养方案管理”中按 专业 + 培养类型 + 年级 上传 2025 级人才培养方案（docx/pdf）。可在线修订提取的文本，保留毕业要求指标全文、课程设置表和课程支撑矩阵。
4. 在“系统设置”中选择注册方式：开放注册 / 注册需审核 / 关闭注册。
5. 在“用户管理”中点击“导入教工名单”，上传 Excel（.xlsx，仅读取第一个工作表）或 UTF-8 CSV。第一行须包含“姓名”和“工号”两列，工号请设为文本以保留前导零。导入后，教工在“教工首次登录”入口同时输入工号和姓名激活，系统告知初始密码 `12345678` 并进入个人设置；此后必须使用“密码登录”。已有工号会跳过，不覆盖原账号。尚未激活的账号需先重置密码才能设为管理员。旧版免密码会话会失效，原免密码账号可通过首次登录激活；已有密码不变。

## 功能

**教师（普通用户）**

- 批量上传检查：一次选择多个 .docx 或 .pdf 大纲，每个文件一行，课程名称默认取文件名（可修改），逐行选择年级（23、24、25、26）和专业（计算机科学与技术、人工智能、物联网工程、中外物联网）；培养类型和对照方案年级（默认 2025，调整须说明）统一设置；
- 每日限额：每个账号每天基础额度为 5 次，管理员可为指定用户追加当天次数，次日按服务器本地时间零点恢复基础 5 次。生成结果即计次（无论大纲是否通过）；接口或解析失败不计次。排队和检查中的任务暂占名额，失败后释放，批量上传及重新检查均受限制。右上角显示剩余次数，次数用完提示联系管理员；
- 查看结果：结论（无明确问题和重大问题即通过）、检查结果（明确问题及重大问题 / 建议修改 / 需核实事项）、逐项检查结果及原文依据；网页与 Word 采用居中标题、检查对象说明和分组段落，每条按 A01 / B01 编号列出位置、问题、整改意见；
- 在结果页醒目的“下载检查结果（Word）”入口下载，也可在上传记录、课程记录中直接下载；支持复制文本、打印、下载原文件；
- 确认上传结果：检查完成后查看结果，由上传者点击“确认上传结果”，保存确认状态和时间；检查结论无论通过与否均可确认，确认不会改动原结果；
- 上传记录：查看自己的全部上传历史，按关键词、检查状态、结果上传状态筛选；批量上传中失败的文件可单独重试，成功记录不重复上传；
- 我的课程：每门课程的历次检查记录；
- 上传前自查：上传页顶部展示检查清单要点，并可下载当前生效清单的完整 Word 文件（含各部分说明和判定规则）。

**管理员**

- 概览、用户管理（导入教工名单并开通首次激活、审核注册、新建、停用/启用、设为管理员、重置密码、删除账号及其文件、增加今日检查次数）；用户姓名和工号集中展示，注册及登录信息展开查看，窄屏表格改为纵向记录，不需要横向滚动；
- 文件与检查记录：全站课程与每次上传的文件、检查结果、结果确认状态及时间，可按用户和确认状态筛选、下载、删除，对失败记录重新检查；用户管理中的检查次数可进入该用户的上传历史，管理员不能代其他用户确认结果；
- 检查清单管理：在线编辑、上传 docx/txt/md 导入（预览确认后保存）、版本管理与设为生效；已被使用的版本修改时自动另存为新版本；
- 培养方案管理、AI 配置（含检查提示词）、系统设置、操作日志。

## 检查规则要点

- 每次检查只使用本次上传的大纲、当前生效清单和对应培养方案，不参考以往记录；
- “需核实”事项（签字、纸质归档、实验记录、成绩单等仅凭大纲无法确认的内容）单列，不计入问题、不影响通过；
- 检查结果不出现 C01/M03 等内部编号、原文摘录和处理先后顺序；A01/B01 等问题编号只用于识别和引用；
- 未预置对应培养方案时仍可检查，需要比对方案的内容列为需核实；
- AI 结果只读；检查失败（接口错误等）可重新检查，已完成的结果不覆盖。

## 数据与备份

所有数据在 `data/` 目录：`app.db`（数据库）、`uploads/`（教师上传的大纲）、`plans/`（培养方案原文件）、`secret.key`（API Key 加密密钥）。备份时停止服务后复制整个 `data/` 目录即可；`secret.key` 丢失后需重新填写 API Key。

## 开发测试工具

- `node scripts/mock-ai.mjs 3999`：本地模拟的 OpenAI 兼容接口（Base URL 填 `http://localhost:3999/v1`），不调用真实模型，用于测试流程；
- `node scripts/make-sample-syllabus.mjs 输出.docx`：生成一份考核表合计故意写错的测试大纲。
- `node --disable-warning=ExperimentalWarning --import tsx --test scripts/user-flows.test.mjs`：针对首次激活、密码登录、每日限额、当天追加次数、并发上传、失败重试、多套 AI 配置及密钥隔离、结果排版和清单下载的回归测试，使用独立临时数据与模拟 AI，不访问真实模型或现有数据。
