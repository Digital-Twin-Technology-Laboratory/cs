## 3 网站首版功能建议

以下是本会话提出的产品建议，尚不是用户逐项确认的功能需求。新会话可在此基础上形成简洁的实现方案，不将全部扩展功能视为既定要求。

建议定位：**教学大纲检查清单与课程整改记录工具**。面向专业负责人、课程负责人和任课教师，既能查看检查要求，也能记录某门课程发现的问题。

### 建议首版包含

1. **查看清单**：按“主要检查项目”“毕业要求与课程矩阵专项检查”“建议完善项目”展示完整内容，支持关键词搜索和按类别筛选。
2. **建立课程记录**：填写课程名称、专业、培养类型、学生年级和对照方案。方案年级默认2025，具体课程可以调整并记录说明。
3. **逐项记录**：每项选择“未检查、未发现问题、存在问题、需核实、不适用”，可以补充说明。
4. **整理课程问题**：一项检查允许记录多个问题，每个问题填写性质、位置、问题描述和整改意见。性质为“明确问题、重大问题、建议修改”；需核实的线索单独保留，不混入已确认问题。
5. **生成整改意见**：按用户确认的两部分汇总，只输出位置、问题和整改意见。基础版本可支持复制文本和打印，Word导出按后续需求实现。
6. **保存记录**：本地首版可采用浏览器保存，并支持导出、导入备份。界面说明保存范围。需要多人共享或跨设备使用时，再采用服务端存储。

网站结构建议为“通用检查清单”“课程检查记录”“本课程整改意见”三个视图。使用真实的检查内容做页面，不用占位文字代替业务内容。

自动解析上传的大纲、AI自动判定问题、多人权限、整改审批流程、统计排名等，属于可另行讨论的扩展功能。当前用户没有提出这些要求。

### 记录结构建议

| 对象 | 建议字段 |
|---|---|
| 检查项目 | 稳定ID、所属部分、名称、检查内容、内容版本 |
| 课程 | ID、名称、专业、培养类型、学生年级、对照方案年级（默认2025）、方案名称、调整说明 |
| 检查记录 | 课程ID、检查项目ID、检查结果、补充说明 |
| 具体问题 | 课程ID、检查项目ID、问题性质、所在位置、当前问题、整改意见 |

检查结果与问题性质分别记录。“存在问题”是一项检查的结果；“明确问题、重大问题、建议修改”是具体问题的性质。可以有一项检查对应多个问题的情况。

## 4 可直接采用的检查清单内容

开头说明：

> 本轮检查统一以2025级相应专业人才培养方案为对照基础，检查教学大纲与培养方案、教学实施及考核材料的一致性。普通本科、专转本等按各自对应的2025级方案核对；具体课程、年级存在不同适用情况的，再据实调整。

### 一 主要检查项目

| 编号 | 检查项目 | 检查内容 |
|---|---|---|
| C01 | 适用版本与课程信息 | 核对适用专业、年级及培养方案版本。课程代码、名称、性质、学分、总学时及理论／实验学时、开课学期与方案一致；文件名和正文信息相符。 |
| C02 | 先修课程与课程衔接 | 先修课程与培养方案开课顺序相符。区分已修课程、同期课程与仅需掌握的基础知识；课程简介中的前后衔接与实际安排一致。 |
| C03 | 毕业要求编号与文字 | 核对一级要求、二级指标编号及指标正文。排查旧版编号、跨专业套用、编号与文字错配、只写简略标题及删改关键能力要求。 |
| C04 | 课程支撑矩阵 | 核对培养方案中本课程应支撑的指标，排查多写、漏写、错列。若标注H／M／L，应与方案一致；支撑强度与考核分值比例分别核对。 |
| C05 | 课程目标与教学内容 | 课程目标符合对应指标内涵，能够通过教学任务和成果进行评价。目标正文与支撑关系表中的表述一致；章节、实验和项目能够落实目标。 |
| C06 | 教学学时与实验安排 | 核算各章节、各实验项目及总学时。实验内容、类型、分组、学时和成果要求合理，与进度表、实验计划、报告及实际任务对应。教学进度表应明确标注对应的实验项目、实施周次或课次及学时，检查是否漏标、漏排，次数和累计学时是否与大纲对应。实验项目数与上课次数分别核对，一个项目可分多次完成；仅写“4+2”等学时数，还应能识别对应的实验安排。 |
| C07 | 考核构成与比例 | 考核项目及各项权重应明确，比例填写确定值，不使用“5%—20%”等区间。分母及包含关系清楚，各课程目标的分项、各考核环节的合计相符，总评为100%；大纲、考核记录和成绩单采用同一计分方案。 |
| C08 | 实验计分与过程评价 | 含实验课程明确实验成绩的归属、权重和汇总方法。每次实验有成绩依据。平时考核形式不少于两种，不含期中考试；考勤占平时成绩不超过50%，计算时明确分母。 |
| C09 | 评价标准与课程思政 | 各考核环节应有可执行的评分要点，各分数档应有明确、可区分的评价描述，不能各档均只写“按照试卷评分标准考核”。引用独立评分标准时，应明确对应关系，并核查具体细则。考核内容及得分点能够证明相应课程目标达成。思政内容与具体知识点、案例、实验或活动相联系。 |
| C10 | 教材与审核手续 | 教材适合课程和本科教学要求，与实际选用、使用一致。审核人签字及相关手续完整；电子版未显示签名时，核查纸质归档件。 |
| C11 | 跨材料一致性 | 核对大纲、教案、进度表、命题双向细目表、试题或项目任务、评分标准和成绩记录。教学内容、学时、目标、项目名称及评分口径相互对应。 |

结果记录须注明具体位置。未取得相关材料时，不直接认定该材料实际不存在。

### 二 毕业要求与课程矩阵专项检查

核对的是“课程设置与毕业要求”的支撑矩阵，以及对应的毕业要求指标原文；“毕业要求与培养目标”的关系表不能替代课程支撑矩阵。

| 编号 | 核查内容 | 常见问题及检查方法 |
|---|---|---|
| M01 | 编号与指标正文 | 检查编号是否属于适用版本，编号与文字是否相互对应。不能只因编号相同就认为指标内容相同。 |
| M02 | 不同专业或年级 | 同名课程在不同专业、年级的指标编号、专业对象、文字内涵及支撑强度可能不同，分别核对后再判断能否共用大纲。当前统一从2025级对应方案开始核对。 |
| M03 | 支撑点的增减 | 逐项核对本课程矩阵行中的非空指标列，大纲不得无说明地增加、删除或替换支撑点。确需调整时，按相应程序统一处理方案与大纲。 |
| M04 | 指标的实质内涵 | 阅读指标全文，识别其要求的能力和成果。不能仅凭“设计”“工具”等标题，将性质不同的课程活动对应到该指标。 |
| M05 | 目标和评价的对应 | 每个支撑点均能对应课程目标、教学任务和考核证据。一个目标支撑多个指标时，分别说明如何实现和评价；不机械限定一对一。 |
| M06 | 大纲内部一致性 | 核对课程简介、目标正文、目标支撑表、章节及实验目标、考核表，避免同一目标在不同位置被改写，或出现无教学任务、无评价证据的支撑。 |

填写方式：在毕业要求栏写适用方案的二级编号及相应指标内容，在课程目标栏写本课程能够实现的具体能力。缩写应保留专业对象和关键能力要求。跨专业共用大纲可分别设置对应表，或采用分专业版本。

专项检查是对主要检查项目的展开。同一实际问题同时涉及C04与M03等项目时，可以关联多个项目，但汇总整改意见时合并为同一个问题。

### 三 建议完善项目

| 编号 | 项目 | 完善方向 |
|---|---|---|
| S01 | 目标表达 | 减少过长、重复或过度拔高的表述，使能力要求与课程学时、实际任务和评价方式相称。 |
| S02 | 评价细化 | 在已有可执行评分细则的基础上，进一步细化得分点、任务难度和评价档次，提高评分的一致性。若缺少具体细则、无法据以评分，应列为明确问题，不归入一般建议完善项。 |
| S03 | 思政与教学资源 | 优化具体案例、讨论和实践活动，完善教材版本、参考资料及在线资源信息。 |
| S04 | 名称与格式 | 统一专业全称、英文名称、术语及小计写法，清理模板提示。一般字号、行距和分页差异不作为重点；文字截断、内容缺失或影响阅读时予以修正。 |

编号C、M、S是交接文件为实现网站增设的稳定标识，不是用户制定的优先级。

## 5 判定时应保留的区别

- **相应方案**：2025是统一起点，不代表所有专业、普通本科和专转本共用同一套指标文字或编号。
- **矩阵层级**：课程支撑毕业要求，与毕业要求支撑培养目标，是不同层次的表。
- **编号与内涵**：编号正确时，仍可能存在指标正文套用或教学任务未落实能力要求的问题。
- **一个目标对应多个指标**：逐项核对教学和评价证据，不直接判为错误。
- **理论与实验目标**：可以承担不同目标，编号不同本身不足以判错。
- **实验项目与课次**：按对应关系和累计学时核查，不设置“一个项目只能上一次课”的规则。
- **评分标准**：缺少可执行细则是明确问题；已有细则、只需提高精细程度时是建议完善。
- **材料不足**：未提供实验记录、电子版未见签字等，应先记录待核实，不直接认定未开展实验或缺少签字。
- **比例规则**：考勤上限计算须明确平时成绩的分母；不另设材料没有规定的实验最低比例。上述过程考核要求来自本院校当前检查材料，不扩写成全国统一要求。
- **审查范围**：网站保存的勾选与填写结果属于用户检查记录。后续如开发自动审查，应另外说明证据来源与待人工核实的判断。
